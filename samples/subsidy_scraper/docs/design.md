## 3. 確定済みの前提

以下は、要件、Phase 1の調査結果、Phase 2・3の実装、ユーザー確認によって確定済みです。

- Python 3.14系と `src` レイアウトを使用する。
- 実処理は `src/subsidy_scraper/app.py` に集約し、必要以上にファイルを分割しない。
- 一覧ページへのHTTPアクセスは原則1回だけとし、直前に3秒待機する。
- 固定Chrome相当User-Agentと30秒タイムアウトを使用する。
- 詳細ページにはアクセスしない。
- 2026年度の見出しから次の年度見出しまでを解析する。
- CSVは `subsidy_kobo_2026.csv` へUTF-8 BOM付きで直接書き込む。
- CSV保存で一時ファイルを経由した置換は行わない。
- 0件の場合はCSVを作らない。
- 自動テストから実サイトへアクセスしない。

## 4. 全体構成

```text
main.py
  └─ CLI処理を呼び出し、終了コードをOSへ返す
       ↓
src/subsidy_scraper/app.py
  ├─ CLIの処理順序とコンソール表示
  ├─ fetch_html()          Web取得
  ├─ parse_subsidies()     HTML解析
  └─ save_subsidies_csv() CSV保存
       ↓
subsidy_kobo_2026.csv
```

新しいCLI専用モジュールは追加せず、Phase 3までと同じ `app.py` にCLI統合関数を追加する案とします。ルートの `main.py` は、その関数を呼び出す薄いエントリーポイントにします。

## 5. 正常時の処理フロー

```text
1. 開始メッセージを表示
2. 3秒待機することを表示
3. Webページ取得中であることを表示
4. fetch_html()を呼び出す
   4-1. 3秒待機
   4-2. 一覧ページへ1回アクセス
5. parse_subsidies()で2026年度を解析
6. 0件でないことを確認
7. 取得件数を表示
8. save_subsidies_csv()でCSVへ直接書き込む
9. 保存完了と保存先を表示
10. 終了コード0で終了
```

正常時の表示案は次のとおりです。

```text
補助金公募情報を取得します。
3秒待機します。
Webページを取得しています。
13件取得しました。
CSVを保存しました。
subsidy_kobo_2026.csv
```

## 6. 責務と公開インターフェース

### 6.1 ルートの `main.py`

- CLI統合関数を呼び出す。
- 戻り値をプロセス終了コードとして返す。
- Web取得、HTML解析、CSV保存の処理は持たない。

### 6.2 `src/subsidy_scraper/app.py`

既存の公開関数は変更せず利用します。

| 関数 | 責務 | 主なエラー |
| --- | --- | --- |
| `fetch_html()` | 待機後に一覧HTMLを1回取得する | `WebFetchError` |
| `parse_subsidies()` | 2026年度のレコードを解析する | `TargetYearNotFoundError`、`HtmlStructureError` |
| `save_subsidies_csv()` | レコードをCSVへ直接保存する | `NoSubsidiesError`、`CsvSaveError` |

Phase 4では、上記を順番に呼び出すCLI統合関数を1個追加する案とします。関数名と戻り値の案は次のとおりです。

```python
def run() -> int:
    """CLI処理を実行し、プロセス終了コードを返す。"""
```

- 正常終了は `0` を返す。
- 処理を継続できないエラーは、利用者向けメッセージを表示して非0を返す。
- CLI統合関数から例外を通常の利用者へそのまま送出しない。

### 6.3 `src/subsidy_scraper/__init__.py`

- CLI統合関数をルートの `main.py` から読み込めるよう公開する。
- 既存の公開関数と例外は維持する。

## 7. エラー処理案

保存処理は、Web取得とHTML解析が正常に終わり、1件以上取得できた後だけ呼び出します。したがって、Web取得失敗、解析失敗、0件の場合は新しいCSVを作りません。

| 状況 | 表示案 | CSV保存 | 終了コード案 |
| --- | --- | --- | --- |
| Web取得失敗 | `WebFetchError` の日本語メッセージ | 呼び出さない | `1` |
| 2026年度なし | 仕様書第22節の2行 | 呼び出さない | `1` |
| その他のHTML構造エラー | 解析できない旨と、サイト構造変更の可能性 | 呼び出さない | `1` |
| 0件 | 仕様書第22節の2行 | 呼び出さない | `1` |
| CSV保存失敗 | `CsvSaveError` の日本語メッセージ | 直接書き込みで失敗 | `1` |

CSVは直接書き込むため、書き込み開始後にエラーが発生した場合、途中までのCSVが出力先に残る可能性があります。自動削除、一時ファイルへの切替、以前のCSVの復元は行いません。

## 8. CSVの設計

- 保存先の基準はレビュー項目D-03で決定する。
- ファイル名は `subsidy_kobo_2026.csv` とする。
- `encoding="utf-8-sig"`、`newline=""` で開く。
- 標準ライブラリの `csv.writer` を使用する。
- ヘッダーは `公開日,補助金名,申請受付期間,詳細URL` とする。
- CSVは出力先へ直接書き込む。
- 既存ファイルの扱いはレビュー項目D-04で決定する。

## 11. レビューが必要な設計判断

以下は仕様から一意に決まらないため、承認前に実装しません。

### D-01: 正常メッセージとエラーメッセージの出力先

- 推奨案: 正常メッセージは標準出力、エラーメッセージは標準エラー出力へ表示する。
- 代替案: 正常・エラーとも標準出力へ表示する。
- 影響: コマンドから出力をリダイレクトするときの扱いが変わる。

### D-02: 異常終了コード

- 推奨案: すべての処理失敗を終了コード `1` に統一する。
- 代替案: エラー種別ごとに異なる終了コードを割り当てる。
- 影響: 統一案は最小構成になる。個別案は外部プログラムから原因を判別しやすいが、仕様とテストが増える。

### D-03: CSVの保存場所

- 推奨案: コマンドを実行したカレントディレクトリへ保存する。
- 代替案: `main.py` があるツールディレクトリへ保存する。
- 影響: 別ディレクトリから起動した場合の保存先が変わる。

### D-04: 既存CSVがある場合

- 推奨案: 確認なしで直接上書きする。
- 代替案: エラーにして既存CSVを維持する。
- 影響: 上書き案は実行が単純になるが、以前のCSVは失われる。エラー案は再実行前に利用者の操作が必要になる。

### D-05: インストールと `python main.py` の成立方法

- 推奨案: プロジェクトを仮想環境へインストールし、ルートの `main.py` から通常のパッケージ名でCLI統合関数を読み込む。READMEでは `uv sync` と `uv run python main.py` を案内する。
- 代替案: `requirements.txt` だけをインストールし、`main.py` が `src` をインポートパスへ追加する。
- 影響: 推奨案は `src` レイアウトの標準的な構成を維持できる。代替案は `python main.py` を直接実行しやすいが、エントリーポイントにパス調整が入る。

### D-06: その他のHTML構造エラーの表示

- 推奨案: `公募情報を解析できませんでした: {詳細}` と `サイト構造が変更された可能性があります。` を表示する。
- 代替案: `HtmlStructureError` の詳細だけを表示する。
- 影響: 推奨案は利用者が状況を理解しやすいが、仕様書にない固定文言が1行増える。

### D-07: READMEのインストール方法

- 推奨案: `uv` を使用する手順だけを記載する。
- 代替案: `venv` と `pip` を使用する手順を記載する。
- 影響: 推奨案はこのリポジトリの開発方法と一致する。代替案は一般的なPython利用者が実行しやすい。両方記載するとREADMEが長くなる。
