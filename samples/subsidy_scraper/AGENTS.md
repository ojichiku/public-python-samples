# subsidy_scraper 開発ルール

## 1. 目的と参照順位

このツールは、中小企業庁の「補助金公募情報」ページから2026年度の情報だけを取得し、UTF-8 BOM付きCSVとして保存する最小構成のPython CLIサンプルです。

作業時は、次の順で文書を参照します。

1. `docs/requirements.md`: 確定した機能要件・非機能要件
2. `AGENTS.md`: 実装と作業のルール
3. `PLANS.md`: 実装順序・進捗・検証内容
4. `docs/HANDOFF.md`: 前回作業が途中で終了した場合の引継ぎ情報

仕様にない機能を追加してはいけません。仕様変更が必要な場合は、実装より先にユーザーへ確認し、承認後に `docs/requirements.md` と `PLANS.md` を同期します。

## 2. スコープ

- 対象URLは `docs/requirements.md` に記載された一覧ページだけとします。
- 2026年度の公開日、補助金名、申請受付期間、詳細URLを取得します。
- 詳細ページにはアクセスしません。
- 出力は `subsidy_kobo_2026.csv` だけとします。
- GUI、Excel出力、定期実行、データベース、複数サイト対応、アクセス制限回避など、仕様書の「今回作らない機能」は実装しません。
- 読みやすいサンプルであることを優先し、将来利用を想定した過度な抽象化やファイル分割は行いません。

## 3. プロジェクト構成

ユーザーの指定により、実装には `src` レイアウトを使用します。この指定は `docs/requirements.md` の第17節にある最小構成例より優先しますが、ファイル数を必要最小限にする考え方は維持します。

想定構成は次のとおりです。

```text
subsidy_scraper/
├── main.py
├── pyproject.toml
├── requirements.txt
├── README.md
├── AGENTS.md
├── PLANS.md
├── docs/
│   ├── requirements.md
│   └── HANDOFF.md        # 作業が途中で終了する場合だけ作成
├── src/
│   └── subsidy_scraper/
│       ├── __init__.py
│       └── app.py
└── tests/
    └── test_app.py
```

- 実処理は `src/subsidy_scraper/` に置きます。
- ルートの `main.py` は `python main.py` を実現する薄いエントリーポイントにします。
- 最初は `app.py` に収まる単純な構成とし、責務が明確に分かれ、分割に実益がある場合だけモジュールを追加します。
- 実行時に生成するCSVをGit管理対象へ含めません。

## 4. 実装ルール

- Python 3.14を使用し、`pyproject.toml` で3.14系に限定します。
- HTTP通信には `requests`、HTML解析には `beautifulsoup4`、CSV出力には標準ライブラリの `csv` を使用します。
- すべてのHTTPアクセスの直前に、必ず3秒以上待機します。待機を無効化する利用者向け設定は作りません。
- 第1版のHTTPアクセスは一覧ページへの原則1回だけとし、詳細URLへアクセスしません。
- タイムアウトは30秒を基準とし、`docs/requirements.md` 第7節で確定した固定のChrome相当User-Agentを送信します。User-Agentのローテーションは行いません。
- 403、429、500系、タイムアウト、DNSエラー、接続エラーが発生した場合は終了し、回避、再試行の乱用、Proxy、User-Agentの切替などは実装しません。
- 2026年度の見出しを基準に解析し、次の年度見出しで対象範囲を終了します。固定位置や2025年度以前の内容に依存しません。
- 実サイトのHTML構造を確認してからセレクタを決めます。想定と異なる場合は推測で実装せず、確認結果と必要な仕様変更を報告します。
- 公開日はHTMLの `YYYY年M月D日` 形式を解析し、ゼロ埋めした `YYYY/MM/DD` 形式へ変換します。
- 公開日変換を除く文字列整形は、前後空白、改行、連続空白の整理だけに限定します。全角・半角変換、名称短縮、日付補完は行いません。
- 公開日、補助金名、詳細URLがすべて同じレコードだけを重複として除外します。
- 相対URLは `urllib.parse.urljoin` で絶対URLに変換します。
- CSVはヘッダー付き、カンマ区切り、`utf-8-sig` で出力します。
- 取得失敗、対象年度なし、0件、CSV保存失敗では、仕様書に従う日本語メッセージをコンソールへ表示し、不完全なCSVや空CSVを残しません。
- 型ヒントを付け、関数の目的が分かりにくい箇所には簡潔なdocstringまたはコメントを記載します。

## 5. テストルール

- HTTPアクセス、待機、HTML入力、CSV出力はテストで差し替えられる境界を設けます。ただし本番の待機を省略できるCLI設定は追加しません。
- 自動テストから実サイトへアクセスしません。最小限のHTMLサンプルとモックを使用します。
- `docs/requirements.md` 第23節の正常系・異常系を網羅します。
- 特に、アクセス前の3秒待機、固定のChrome相当User-Agent、2026年度だけの抽出、公開日の `YYYY/MM/DD` 変換、期間表記3種類、相対URL、重複除外、UTF-8 BOM、エラー時にCSVを作らないことを確認します。
- 実装完了時は少なくとも全pytestと、利用する静的チェック／フォーマッタ、`git diff --check` を実行します。
- 実サイトでの確認はアクセス回数を最小限にし、必ず3秒待機を含む実装経由で行います。

## 6. タスクとコンテキストの管理

- `PLANS.md` のフェーズ単位で作業し、一度に複数フェーズを抱え込みません。
- 各フェーズの開始時に、必要な文書と対象ファイルだけを読みます。無関係な既存サンプルを広く読み込まないようにします。
- 各フェーズは、成果物、検証結果、`PLANS.md` の進捗更新までを一つの完了単位とします。
- 後続フェーズで必要な判断、HTML構造、コマンド、未解決事項は文書へ残し、会話履歴だけに依存しません。
- ユーザーがフェーズごとの確認を求めた場合は、その承認前に次のフェーズへ進みません。

## 7. 途中終了時の引継ぎ

予定したフェーズを完了できないまま作業を終える場合は、終了前に `docs/HANDOFF.md` を作成または更新します。

`docs/HANDOFF.md` には最低限、次を記載します。

- 現在の目標と作業中のフェーズ
- 完了した作業
- 未完了の作業と、次に行う具体的な1手
- 確定した判断と、その根拠
- 変更したファイル
- 実行した検証、結果、未実施の検証
- エラー、ブロッカー、注意点
- Gitのブランチと作業ツリーの状態

再開時は `docs/HANDOFF.md` を最初に読み、実ファイルとGit状態を照合してから作業します。引継ぎ対象がすべて解消され、予定作業が完了した時点で `docs/HANDOFF.md` を削除します。
