# wordpress-draft-publisher-codex 開発ルール

## ツールの目的

このツールは、Markdownで書いた記事をWordPress REST APIへ送信し、WordPressに下書き投稿するための最小限の投稿ツールです。

本格的な管理画面やWordPressプラグインではなく、ローカルのMarkdownファイルを読み込んで下書き投稿・更新するサンプルとして扱います。

## 実装方針

- 読みやすさを優先し、処理の流れが追いやすいコードにします。
- 過度な抽象化は避け、サンプルとして理解しやすい構成を保ちます。
- 投稿ステータスは必ず `draft` にします。`publish` は使いません。
- 既存記事の判定は、WordPress投稿のスラッグ検索で行います。
- 同じスラッグの記事が存在する場合は、新規投稿ではなく既存記事を更新します。
- 投稿または更新に成功したMarkdownファイルだけを `done` フォルダへ移動します。
- エラーが発生したMarkdownファイルは移動せず、元のフォルダに残します。

## 認証情報の扱い

- WordPressの接続情報は `.env` から読み込みます。
- `.env` や実際の認証情報をGitHubへ公開してはいけません。
- READMEには `.env.example` を使った設定例を記載します。
- サンプル値以外のURL、ユーザー名、アプリケーションパスワードをコミットしないでください。

## WordPress API操作

- WordPress REST APIの投稿エンドポイントを使います。
- カテゴリ名とタグ名からIDを取得します。
- 存在しないカテゴリ・タグは自動作成します。
- カテゴリ名やタグ名の入力ミスで新しい項目が作成されるため、READMEで注意喚起します。
- APIエラー時は、ステータスコードやレスポンス本文など、原因調査に使える情報を表示します。

## ファイル移動

- 成功したMarkdownファイルは `done` フォルダへ移動します。
- `done` フォルダが存在しない場合は自動作成します。
- 同名ファイルが `done` フォルダに存在する場合は上書きします。
- ファイル移動に失敗した場合は、エラーとして扱い、分かりやすいメッセージを表示します。
