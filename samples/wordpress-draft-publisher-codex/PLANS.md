# wordpress-draft-publisher-codex 実装計画

## 1. 接続情報を読み込む

- `.env` を読み込みます。
- `WP_URL`、`WP_USER`、`WP_APP_PASSWORD` を必須項目として確認します。
- `.env` が存在しない場合や必須項目が不足している場合は、分かりやすいエラーメッセージを表示します。

## 2. 投稿対象フォルダを決める

- コマンドライン引数でMarkdownファイルの格納フォルダを受け取ります。
- 引数がない場合は、デフォルトで `draft` フォルダを対象にします。
- 対象フォルダが存在しない場合は、エラーとして処理を終了します。

## 3. Markdownファイルを読み込む

- 対象フォルダ内の `.md` ファイルを処理対象にします。
- Markdownファイルが存在しない場合は、分かりやすいメッセージを表示します。
- 複数ファイルがある場合は、1ファイルずつ処理します。

## 4. Markdownから投稿情報を取得する

- Markdownから以下の項目を取得します。
  - タイトル
  - スラッグ
  - カテゴリ
  - タグ
  - 本文
- 必須項目が取得できない場合は、そのファイルをエラー扱いにします。
- エラーになったファイルは `done` に移動しません。

## 5. 本文MarkdownをWordPress投稿用に変換する

- 本文部分のMarkdownを、WordPressブロックエディターで扱いやすい形式へ変換します。
- 単純なHTML一括変換だけにするとクラシックブロック扱いになりやすいため、可能な範囲でGutenbergブロックコメント付きのHTMLへ変換します。
- コードブロックは、通常の段落ではなくコードブロックとして扱われるように変換します。
- 見出しは、本文内の `##` から `######` までを対象にします。
  - `##` は見出しレベル2として扱います。
  - `###` から `######` は、それぞれ見出しレベル3から6として扱います。
  - 本文のタイトルは投稿タイトルとして別に扱うため、本文内の `#` 見出しは原則使わない想定にします。
- 箇条書き、番号付きリスト、太字、リンク、コードブロック、表を扱えるようにします。
- 可能であれば、引用と水平線もWordPress投稿用に変換します。
  - 引用は引用ブロックとして扱います。
  - 水平線は区切り線ブロックとして扱います。

## 6. カテゴリ・タグを取得または作成する

- カテゴリ名からWordPress上のカテゴリIDを取得します。
- タグ名からWordPress上のタグIDを取得します。
- 存在しないカテゴリ・タグはWordPress REST APIで作成します。
- APIエラー時は、そのファイルの処理を失敗として扱います。

## 7. スラッグで既存記事を検索する

- WordPress REST APIで同じスラッグの投稿を検索します。
- 投稿が見つかった場合は更新対象にします。
- 投稿が見つからない場合は新規投稿対象にします。

## 8. 新規投稿または更新を行う

- 投稿ステータスは必ず `draft` にします。
- 新規投稿時は投稿作成APIを呼び出します。
- 既存投稿がある場合は投稿更新APIを呼び出します。
- 成功時は投稿ID、ステータス、編集URLなどを表示します。

## 9. 成功したMarkdownファイルをdoneへ移動する

- 投稿または更新が成功したファイルだけを `done` フォルダへ移動します。
- `done` フォルダが存在しない場合は作成します。
- 同名ファイルが存在する場合は、日時を付けたファイル名で移動します。
- 移動に失敗した場合は、分かりやすいエラーメッセージを表示します。

## 10. READMEに使い方を書く

- ツールの概要を書きます。
- 必要な準備と依存ライブラリのインストール方法を書きます。
- `.env` の設定例を書きます。
- Markdownファイルの書き方を書きます。
- 実行方法を書きます。
- 成功時に `done` フォルダへ移動されることを書きます。
- 同じスラッグの記事がある場合は更新されることを書きます。
- カテゴリ・タグ名の入力ミスに注意することを書きます。
- `.env` をGitHubに公開しないことを書きます。
