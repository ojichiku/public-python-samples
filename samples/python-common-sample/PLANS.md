# 共通機能 開発計画（PLANS）

本 PLANS.md は、
**共通機能（common パッケージ）を開発・追加・修正する際の作業手順と進め方**を定める。

AGENTS.md のルールに従い、個々の機能仕様は `specs/` 配下の spec ファイルで管理し、
ここでは「作業プロセス」「優先順位」「進行フロー」を定義する。

---

## 1. 開発の基本フロー

共通機能を新規追加・修正する際は、必ず次の順序で作業する。

### **ステップ 1：仕様（spec）を作る / 修正する**

1. `specs/` 配下に `<機能名>.md` を作成する
   （例：`logging.md`、`config.md`、`paths.md`）
2. 以下の内容を明記する：

   * 目的
   * 要件
   * 仕様（API・動作・パラメータなど）
   * 成果物（必要なファイル）
   * テスト観点
3. 機能追加・変更があった場合は、spec を必ず更新する。

※ spec に記載されていない内容を実装に追加することは禁止。
仕様に追加が必要なら spec → 実装 の順で進める。

---

### **ステップ 2：実装を行う**

1. `src/common/` 以下にモジュールを作成・修正する。
2. AGENTS.md のルールに従って記述する：

   * 日本語コメント・docstring
   * 型ヒント必須
   * src レイアウトで配置
   * 標準ライブラリ優先
3. spec に書かれた API と動作を完全に満たしていること。

---

### **ステップ 3：テストを書く（pytest）**

1. `tests/` 配下に `<test_file>.py` を作成（例：`test_logging.py`）
2. spec の「テスト観点」をすべて網羅する。
3. 追加・変更した部分だけでなく、既存機能に影響がないかも確認する。

---

### **ステップ 4：テスト実行**

* `pytest` を実行し、すべてのテストが通ることを確認する。
* テストが通らない場合は、実装ではなく **spec と AGENTS.md を基準に修正点を判断**する。

---

### **ステップ 5：完成として反映**

* 必要に応じて README や他 spec のリンクを更新。
* PLANS.md で次の開発対象へ進む。

---

## 2. コード生成エージェントの作業指針

ChatGPT / Codex / Copilot などのエージェントが生成するコードは、以下を厳守する：

1. **AGENTS.md と spec を必ず参照し、違反しないこと。**
2. 実装前に spec が存在しない場合 → spec 作成から開始すること。
3. 実装変更が必要になった場合 → spec を先に更新すること。
4. テストを必ず作成し、実装とセットで出力すること。
5. 解釈に迷う場合は AGENTS.md を最優先する。

---

## 3. 作業ルール（細則）

* 既存コードの破壊的変更は禁止
  → 必要な場合は spec と AGENTS.md を更新し、変更理由を明記
* 実装は小さな単位に分割して行う
  → 1 ファイル / 1 クラス / 1 API 単位で PR 可能な粒度
* 仕様追加・変更が発生したら
  → spec → 検証 → 実装 → テスト → 確認 の順で進める
* 共通機能にアプリ固有ロジックを追加しない
  → 専用パッケージを別に作る

---

## 4. 進捗管理

* 機能単位で「spec → 実装 → テスト → 完了」の進行状況を管理する。
* 新しい共通機能を追加する場合は PLANS.md に追記し、順番を整理する。

---

## 5. 今後の拡張の運用ルール

* 一度リリースした API を変更する場合、後方互換性を最優先する。
* 大きなリファクタリング時も spec を改訂し、理由を明文化する。
* エージェント生成コードに依存しすぎないよう、仕様を常にドキュメントとして残す。
