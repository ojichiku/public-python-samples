# 共通機能：メッセージ取得機能（messages）仕様書

## 1. 目的

本仕様は、アプリケーション全体で利用する **ユーザー向けメッセージを外部ファイルで管理する仕組み** を定義する。

目的は以下の通り：

- メッセージを **ID で統一管理**し、CLI・GUI など異なるUIで同じ文言を使用できるようにする
- 実装コード中にユーザー向けメッセージをベタ書きしない
- 将来の **多言語対応（日本語 / 英語など）** を容易にする
- メッセージへの動的値の埋め込みを、**{0}, {1}, {2}... の位置指定プレースホルダー**で表現する

---

## 2. 全体構成

### 2.1 メッセージファイルの配置

メッセージファイルは `config/` ディレクトリに置く。

例：

```

config/messages_ja.ini
config/messages_en.ini（将来追加）

```

### 2.2 ファイル形式

- **INI形式**を採用する
- セクションは **[messages]** のみ

---

## 3. メッセージIDと値

### 3.1 メッセージID

- メッセージIDは **INIファイルのキー名そのもの** とする
- 厳密な命名規則は定義しないが、以下を推奨：
  - 英大文字＋数字＋アンダースコア：例 `MSG_CONFIG_NOT_FOUND`
  - 一意に識別できればよい

### 3.2 メッセージ本文

- 値は **テキスト**（日本語または英語）
- プレースホルダー `{0}`, `{1}`, `{2}`, ... を含む場合がある

---

## 4. プレースホルダー仕様（{0} スタイル）

### 4.1 採用方式

- プレースホルダーは **位置指定形式 `{0}`, `{1}`, `{2}`, … のみ**採用する
- `{name}` の名前付き形式は本仕様の範囲外（将来拡張可能）

### 4.2 動作仕様

メッセージ取得時に、次のルールで置換する。

| 状況                                  | 動作                                         |
| ------------------------------------- | -------------------------------------------- |
| 必要な引数が足りない                  | 対応する `{n}` は **置換されずそのまま残す** |
| 引数が多い                            | 余った引数は **無視する**                    |
| プレースホルダーが不正（例: `{abc}`） | **そのまま残す**                             |
| 値に `{0}` が複数ある                 | すべて同じ値で置換する                       |

### 4.3 エスケープ

- `{` や `}` を文字として使いたい場合のエスケープルールは **本仕様では定義しない**  
  → 必要になった時点で拡張する

---

## 5. メッセージファイルの例（日本語版）

`config/messages_ja.ini`

```ini
[messages]
MSG_CONFIG_NOT_FOUND = 設定ファイル {0} が見つかりません。
MSG_INVALID_PARAM    = パラメータ {0} の値「{1}」は不正です。
MSG_UNKNOWN_ERROR    = 予期しないエラーが発生しました。
```

---

## 6. 多言語対応

* 言語ごとに別ファイルを作成する（例：`messages_ja.ini`, `messages_en.ini`）
* ファイル名の命名規則は `messages_<locale>.ini`

  * 例：`messages_ja.ini`, `messages_en.ini`
* 取得処理は `locale` を引数に受け取り、該当ファイルから読み込む想定

---

## 7. 想定されるAPI（行動仕様のみ）

※ 実装コードは本仕様では定義しない（README または別途コード側で定義）

### メッセージ取得関数の動作仕様

```
get_message(msg_id, *args, locale="ja")
```

* `msg_id` に対応するメッセージ本文を取得
* `{n}` を `args[n]` で置換
* IDが存在しない場合
  → `"[" + msg_id + "]"` を返す（推奨のフォールバック動作）

---

## 8. 成果物

本仕様に基づき作成する成果物は次の通り。

### 8.1 メッセージファイル（必須）

* `config/messages_ja.ini`
* 形式は INI
* セクション `[messages]`

### 8.2 実装（messages モジュール）

* ファイル名：`src/common/messages.py`
* 内容：

  * INIファイルを読み込み、メッセージを ID で取得する機能
  * `{0}` プレースホルダーの置換ロジック
  * ロケールに応じたファイル読込

※ 実装コード自体は本 spec には含めない

### 8.3 テストコード

* ファイル名：`tests/test_messages.py`
* テスト観点：

  * メッセージID → 正しい文言が取得できる
  * `{0}`, `{1}` が引数で正しく置換される
  * 引数不足／余分／不正プレースホルダー時の挙動
  * IDが存在しない場合のフォールバック

---

## 9. 将来拡張

以下は仕様に含めないが、将来追加の余地がある：

* `{name}` 形式（名前付きプレースホルダー）
* 多言語自動切り替え
* メッセージ階層構造（エラー/警告/情報など）
* エスケープ文字の正式定義
